# Welcome to schoolboard.net

## Purpose

This chapter introduces schoolboard.net and explains how this documentation suite is organized. It also establishes the platform philosophy: board meeting materials should be accessible, searchable, structured, and easy for districts to maintain.

## Prerequisites

Before using this guide, readers should have:

- A schoolboard.net user account.
- An assigned administrator or content-author role, when applicable.
- Access to the district's schoolboard.net site.
- A basic understanding of board meeting agendas and public meeting materials.

## Overview

schoolboard.net is designed to help districts publish board meeting materials in accessible web-based formats. Instead of relying primarily on PDF packets, the platform encourages structured HTML content, expandable agenda sections, searchable meeting records, and workflows that support WCAG 2.1 AA accessibility practices.

This documentation is intended to teach both the software workflow and the publishing discipline behind it. Each topic explains what to do, why it matters, and how the task supports accessibility, transparency, and long-term records management.

## How this guide is organized

The Administrator Training Guide is organized around common district workflows:

1. Signing in and using the dashboard.
2. Managing users, groups, and permissions.
3. Creating and publishing accordion agendas.
4. Adding sections, agenda items, nested items, files, and Expandable HTML content.
5. Sending notifications and managing revisions.
6. Preparing accessible content from Microsoft Word, Google Docs, and AI-assisted conversion tools.
7. Troubleshooting common issues.

## Accessibility notes

Accessible documentation should use clear headings, meaningful links, descriptive image text, readable tables, and procedures that do not depend on color alone. These same principles apply when creating board materials inside schoolboard.net.

## Best practices

Create content directly in structured HTML whenever practical. Use Microsoft Word or Google Docs as drafting tools, but review and clean the final HTML before publication.

## Administrator notes

District administrators should establish internal publishing standards before the first live agenda is created. Consistent headings, file naming, revision notes, and notification practices will reduce support issues and improve public access.

## AI tip

AI tools such as Claude, Gemini, and ChatGPT can help convert Word or Google Docs content into cleaner HTML. Always review AI-generated HTML before importing it into schoolboard.net.

## Troubleshooting

| Problem | Possible cause | Resolution |
|---|---|---|
| A user cannot access an administrative page. | The user may not have the correct role or group membership. | Review the user's account, roles, and group membership. |
| Agenda content looks inconsistent after paste. | Formatting may have been copied from Word or Google Docs. | Use clean HTML, paste cleanup tools, or AI-assisted conversion before publishing. |
| A screen reader does not announce content clearly. | Headings, links, or Expand Text labels may not be descriptive. | Review headings, link text, and Expand Text labels for accessibility. |
