# Core Concepts

## Quick Summary

This page explains the basic ideas used throughout schoolboard.net.

Learn these first. The rest of the documentation will be easier.

## User

A user is a person who can sign in to schoolboard.net.

Examples include:

- Board Clerk
- District Administrator
- Board Member
- Group Administrator
- Staff member

## Group

A group is a collection of users and related content.

A district may use groups to separate boards, committees, departments, or private work areas.

## Group Administrator

A Group Administrator can manage certain content or people inside a group.

This role helps districts share work without giving everyone full system access.

## Permission

A permission controls what a user can see or do.

For example, one user may be allowed to create agendas. Another user may only be allowed to view published agendas.

## Accordion Agenda

An Accordion Agenda is an agenda that opens and closes in sections.

This keeps the page easier to read.

A person can open only the section or item they want to see.

## Agenda Section

An Agenda Section is a major part of an agenda.

Examples:

- Call to Order
- Consent Agenda
- Public Comment
- Reports
- Action Items
- Closed Session

## Agenda Item

An Agenda Item is one specific item inside an agenda section.

It may include text, files, links, or expandable content.

## Nested Agenda Item

A Nested Agenda Item is an item inside another item.

Use nested items when an agenda needs a clear substructure.

## Expandable HTML

Expandable HTML is content that opens when a user selects it.

It is useful for long text that should not make the agenda page too crowded.

## Public File

A Public File can be viewed by people who are allowed to see the public agenda.

## Private File

A Private File is limited to users with the correct permission.

Private files should be used carefully.

## Notification

A Notification tells users or the public that something has been published or changed.

## Revision

A Revision is a saved version of content.

Revisions help track changes over time.

## Best Practice

Use the simplest structure that works.

Do not create extra groups, nested items, or permissions unless they are needed.
